# A-011：FAIL 输出格式（结论＋证据＋怎么修）

> 通用版（P0-1，2026-10-10）：原内部范本 `a011-fail-rewrite.md` 的去项目化转写，
> 结构与验收标准不变，示例改为通用站点。

## 格式（7 节，缺一不可）

```
✖ <RULE-CODE> <一句话结论> [FAIL · <门禁>]
  位置: <文件:行 或 选择器，精确到可定位>
  现状: <发生了什么——数据，非形容词>
  为什么重要: <一句话讲清该门禁存在的理由>
  怎么修: <具体可执行的改法：diff/命令/选项，不只说"请修复">
  验证: <修完后如何确认：重跑哪项、期望什么输出>
  关联: <立案记录/报告链接，便于追溯>
```

## 示例

```
✖ TYPE-SCALE  .hd-num 字体未命中字阶表  [FAIL · A++ 硬扫]
  位置: index.html <style> · .hd-num{font-size:1.7rem}
  现状: 1.7rem 在 16px 基准下 ≈ 27.2px，不在字阶表 (12/14/16/20/24/32/40) 内
  为什么重要: 相对单位绕开了字阶检查——字阶是全站视觉一致性的唯一刻度
  怎么修: font-size:1.7rem → font-size:24px（若语义=H2）或 32px（若语义=H1）
  验证: 重跑 A++ 硬扫，.hd-num computed font-size ∈ 字阶表
  关联: 立案记录 <release-id>（P2）
```

## 验收标准

- 缺"怎么修"的 FAIL 输出视为门禁报告本身不合格（A-011 铁律）。
- 首行机器可 grep（`✖ <RULE-CODE>` 前缀）。
